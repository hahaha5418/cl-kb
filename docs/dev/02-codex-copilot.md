# 让 AI 帮你写代码（新手也能用）

## 一句话看懂

**AI 编程助手 = 一个随叫随到的程序员同事**：你用大白话描述想要什么，它写出草稿，你负责判断和验收。

## 它到底是什么

写代码最累的其实不是「敲键盘」，而是三件事：**想清楚要做什么**、**查资料**、**调错误**。AI 编程助手主要帮你干后两件。

> 类比：它像一个刚入职、手速极快的实习生——**写得飞快，但不一定对**，所以你必须当那个验收的人。

## 常见工具怎么选

| 工具 | 是什么 | 适合谁 |
| --- | --- | --- |
| **对话助手（ChatGPT / DeepSeek / 豆包等）** | 在网页或 App 里直接问 | **纯新手首选**，零安装 |
| **Cursor** | 自带 AI 的编辑器 | 想整段改文件的人 |
| **GitHub Copilot** | 编辑器里的自动补全插件 | 已经在写代码的人 |
| **通义灵码 / CodeGeeX** | 国产编程插件 | 追求**国内网络稳定、中文好** |

> 新手建议：先用**对话助手**。等你能说清需求了，再考虑装编辑器插件。

## 新手实操：六步做出第一个小程序

1. **想清楚你要什么**。先别碰电脑，用一句中文写下来，比如「**做一个把中文按句号拆开的网页小工具**」。
2. **打开任意一个对话助手**，把这句话原样发过去，并加上一句「**我是完全的新手，请把每一步都说清楚**」。
3. **拿到代码后，先让它解释**。追加一句：「**请逐行用大白话解释这段代码在干什么**」。
4. **让它告诉你怎么运行**。追问：「**我该把这个文件放在哪、怎么打开它？请说具体路径和操作**」。
5. **照着做，遇到报错就原样贴回去**。把红色错误信息整段复制，发给它说「**出现了这个错误，请帮我修**」。
6. **确认能用之后，再提新需求**。一次只加一个功能，比如「再帮我加一个清空按钮」，**别一次提五个**。

> 关键点：**第 5 步最重要**——把报错原样丢回去，AI 修 bug 的成功率远高于它一次写对。

## 让 AI 写出好东西的提问公式

记住这个顺序，效果会好很多：

> **你是谁 + 要做什么 + 有什么限制 + 给一个例子**

套用示范（直接照着改就能用）：

- **你是谁**：「你是一位有耐心的编程老师」
- **要做什么**：「帮我写一个把中文按句号切分成句子的小工具」
- **有什么限制**：「**不要用我看不懂的术语，每行都要有中文注释**」
- **给一个例子**：「比如输入『你好。世界』，应该得到『你好。』和『世界』两句」

## 新手常踩的坑

- **直接运行它写的危险命令**：看到「**删除文件**」「**格式化**」「**安装某个东西**」这类操作，**先问清楚再执行**。
- **把密码、密钥贴给 AI**：涉及真实账号信息，**先打码**再发。
- **它自信地胡说**：代码跑不通很正常，把报错丢回去让它改，**来回两三轮通常就好了**。
- **一次提太多要求**：需求越散，它越容易跑偏。**一次只做一件事**。

## 它不适合什么

- **需要绝对正确的场景**（财务结算、医疗、法律文书）——AI 会出错，必须人工复核。
- **你完全看不懂输出**：如果连它在写什么都判断不了，就先补基础概念。
