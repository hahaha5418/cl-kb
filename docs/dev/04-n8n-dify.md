# 让 AI 每天自动干活（工作流入门）

## 一句话看懂

**工作流就是把「触发 → 处理 → 输出」串成一条自动跑的流水线**。比如：每天早上 8 点自动抓新闻 → AI 写摘要 → 发到你的邮箱。

## 它到底是什么

你手动做一件事，通常是三个动作连起来的：

1. **什么时候做**（触发）：比如「每天早上 8 点」
2. **做什么**（处理）：比如「抓新闻、让 AI 总结」
3. **结果放哪**（输出）：比如「发到邮箱 / 存到表格」

工作流工具做的事情，就是让你**用拖拽的方式把这三段连起来**，然后它就**7×24 小时替你跑**。

> 类比：就像工厂的流水线——原料从一头进去，经过几道工序，成品从另一头出来，全程不用人盯。

## 新手实操：七步搭出「每天自动发 AI 简报」

1. **确定你要的成品**。先写清楚一句话目标，比如「**每天早上 8 点，把 3 条 AI 新闻摘要发到我邮箱**」。
2. **注册并新建一个工作流 / 应用**。国内平台用手机号即可登录。
3. **添加「定时触发」节点**，把时间设成**每天 8:00**。这是整条流水线的开关。
4. **添加「读取新闻源」节点**。填入你喜欢的新闻网站地址，先选**一个**就好。
5. **添加「AI 处理」节点**。在提示词框里写清楚要求，比如「**把下面这些标题各写成一句不超过 40 字的中文摘要**」。
6. **添加「发送」节点**。选邮箱、飞书或微信，填好接收地址。
7. **点「测试运行」**，确认收到一条内容；没问题就点「**启用**」，它从此开始自动运行。

> 关键点：**第 7 步一定要先测试再启用**，否则一个配置错误会让你每天都收到一封错误邮件。

## 让流程更稳的三个习惯

- **先跑通最短链路**：只用「定时 → AI → 发送」三个节点，成功后再加功能。
- **每加一个节点就测一次**：一次性加五个节点，出错时你根本不知道是哪一个的问题。
- **给关键节点改名**：把「HTTP Request 2」改成「**读取量子位新闻**」，过两周你还能看懂。

## 新手常踩的坑

- **节点之间字段名对不上**：上一个节点的输出叫「title」，下一个却填「标题」，就会失败。**报错先看字段名**。
- **密钥直接写在节点里**：要用平台提供的「**凭据管理**」功能单独保存，方便更换也更安全。
- **忘了设执行上限**：某些节点可能反复重试，**烧掉大量额度**。设置一个每日执行次数上限。
- **一上来就想做复杂的**：从「一条新闻 → 一句摘要」开始，跑顺了再扩展。

## 它不适合什么

- **只需要做一次的事**：手动做更快，不用搭流水线。
- **要求实时响应**：工作流通常有延迟，不适合秒级场景。
